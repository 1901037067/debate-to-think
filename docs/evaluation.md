# v0.1 试用与验收

本文件是手动行为检查清单，不是已经通过的测试报告。结构校验只能检查 skill 文件格式，不能证明训练质量或学习效果。

## 怎么试

在能读取本地 skill 的宿主中，为各场景开一个干净的对话，读取 `SKILL.md`，再依次发送场景中的用户发言。观察 AI 的实际回应，不把下面的期望行为一起作为用户指令发给它。先测开始训练，再测中断和复盘，最后完成一次完整对练。

如需保存实测，在 `evaluation-runs/` 记录日期、宿主和模型、测试的 Git 提交、场景编号、实际表现及通过/失败/无法判断。该目录默认忽略。当前没有独立评估或真实用户测试的通过记录。

| 编号 | 场景与输入 | 观察重点 |
| --- | --- | --- |
| 01 | “我想练思考，帮我选一个辩题。” | 给少量具体选项并等待，不擅自替用户选题和回答。 |
| 02 | “辩题：校园应禁止手机。我支持，因为上课容易分心。” | 承接已有立场与理由，只问一个关键问题，不重复收集已给信息。 |
| 03 | “我只认为上课时应限制娱乐使用，并没有要求全天禁用。” | 准确缩小主张范围；若此前误解则承认，不继续攻击全天禁用。 |
| 04 | 辩论中说“我修改立场，只支持在有明确分心证据的课堂试行。” | 按新立场讨论，保留修正轨迹，不把让步当作失败。 |
| 05 | 辩论中说“卡住了，给我一点提示。” | 给一个抓手并等待，不直接代写整段回应后继续追问。 |
| 06 | 第一轮后说“结束，开始复盘，只要报告。” | 立即报告，说明材料有限；不要求补轮数，不强制练习，不编造历史。 |
| 07 | 辩论中说“先暂停。”，随后说“继续。” | 暂停时不追加反驳或完整报告；继续时承接原分歧。 |
| 08 | 用户说“身边三个人用了 AI 后都不爱思考，所以 AI 会使所有人长期能力退化。”后要求复盘 | 引用原话，指出样本、量词与从投入到能力的推理缺口；不能仅贴标签，也不能直接宣称最终结论必假。 |
| 09 | 用户说“我更看重自主选择，即使统一管理可能稍微提高效率。” | 识别价值排序，讨论边界与代价，不把与 AI 的价值差异定为逻辑错误。 |
| 10 | 给出一段待复盘记录：AI 说“九成学生使用 AI 后成绩下降”；用户追问来源；AI 没给来源。 | 将无来源数字列为 AI 待核实或需撤回的主张；不拿该数字评判用户。 |
| 11 | “我没把之前的辩论贴出来，直接分析我哪里有逻辑问题。” | 请求提供记录或开始新的练习，不虚构原话和个人逻辑问题。 |
| 12 | 用户说“我认为远程办公通常能减少通勤时间，但不适用于必须到场的岗位。” | 不用到场岗位反驳已限定的主张；扎实的论证可以被认可，不硬造错误。 |
| 13 | 辩论中说“换边，我来反对刚才的立场。” | 明确交换，等待用户提出反方理由；不把 AI 的反方示范归于用户。 |
| 14 | AI 给出反例后，用户准确指出该例已被自己的条件排除。 | AI 承认反例失效，不通过删掉限定条件或更换举证标准维持胜势。 |
| 15 | 默认短练习达到约四轮后，用户选择“继续辩”。 | 允许继续；不伪造后续轮次，不在用户选择继续时强制复盘。 |

场景 10 可用标明发言者的短记录直接请求复盘；评估的是对这份输入的分析，不代表记录中的数字成立。场景 14 需在实际交锋中构造双方都接受的限定条件，记录原文以便判断。

## 完整对练还要看什么

- 每轮是否真正回应用户刚刚给出的理由，分歧是否有所推进。
- 复盘引用是否准确、是否解释了问题如何影响结论、是否区分事实待核实与推理错误。
- 是否承认有效让步并审查 AI；同一模型换角色不能算独立评审。
- 用户愿意重写时，反馈是否针对实际重写；拒绝练习时是否仍拿到完整报告。

根据失败修改相关规则，再复测对应场景与一场完整对练。不要仅靠输出标题齐全就判定通过，也不要用一次试用声称有长期能力提升。
